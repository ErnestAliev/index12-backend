# INDEX12 MCP

Локальный MCP-сервер для Codex через stdio. Пять инструментов читают выбранную рабочую область: поиск справочников, полная финансовая сводка, исходные операции, остатки счетов и состояние подключения. Сервер не вызывает OpenAI API и не меняет существующий ИИ-модуль.

## Запуск

1. `npm ci` в backend.
2. Скопировать `mcp/config.example.json` в `.mcp.local.json`, указать ID владельца и принадлежащей ему рабочей области. Файл исключён из Git. Область закреплена явно и не меняется вслед за веб-интерфейсом. Доступ к чужим и расшаренным областям не поддерживается.
3. База: переменная `INDEX12_MCP_DB_URL` или `DB_URL` из backend `.env`. Предпочтителен отдельный пользователь MongoDB с ролью только чтения. URI никогда не помещается в результаты инструментов или конфигурацию Codex.
4. `codex mcp add index12 -- /absolute/path/to/node /absolute/path/to/index12-backend/mcp/server.cjs`.
5. Открыть новую беседу Codex. Пример: «Используй INDEX12. Оцени Пушкина за октябрь 2026: доходы, расходы, общие расходы отдельно, изменения по контрагентам».

При необходимости путь к конфигурации задаётся `INDEX12_MCP_CONFIG`. MCP запускается из любого рабочего каталога. Не публиковать `.env` и `.mcp.local.json`.

## Расчёты и границы

- Итоги по всей области, затем фильтры. Лимит страницы операций не ограничивает итоги. Более 250000 исходных строк или справочных сущностей — явная ошибка без частичных результатов; для следующего масштаба нужен агрегатор в MongoDB.
- Суммы считаются в целых тиынах, возвращаются десятичными строками KZT. Факт/план определяется календарной датой Asia/Almaty относительно `asOf`, а не банковским подтверждением оплаты. Сохранённый `dateKey` INDEX12 имеет приоритет.
- Распределённый родитель исключён, дочерние доли учитываются. «Все проекты» учитывается один раз отдельной статьёй, без распределения. При фильтре проекта общие расходы возвращаются отдельно.
- Номинальные доходы/расходы отделены от денежных: взаимозачёт уменьшает денежное поступление и не списывается повторно. Связанные расходы ищутся по всей области, включая другие периоды.
- Парные старые переводы объединяются только при равных суммах и одинаковом дне. Повреждённые группы отмечаются в diagnostics и не маскируются под операционные доходы/расходы; остатки при таких группах ненадёжны.
- Личные изъятия отдельно от расходов, внутренние переводы отдельно от результата. Акты, списания и удалённые операции исключены. Неизвестные виды отражаются в diagnostics, не превращаются автоматически в доходы.
- `operatingResult` — результат внесённых доходов и расходов. Он не подтверждает бухгалтерскую чистую прибыль; кредиты, налоги, полнота начислений и амортизация требуют отдельного разбора по категориям и документам.
- Скрытые счета включены. Метка скрытия — настройка интерфейса, не отсутствие денег. Начальный остаток не имеет исторической даты, поэтому исторические остатки воспроизводят текущую модель INDEX12.
- Все запросы перечитывают данные. Общей транзакционной фотографии между инструментами и страницами нет. При изменении базы нужно повторить анализ. Ошибки чтения не подменяются нулевым результатом.
- Данные доступны только настроенному владельцу, а инструменты предоставляют лишь чтение. Прямой SQL/Mongo, выполнение кода и изменение операций не доступны. Локальный процесс имеет доступ к URI из окружения; для ограничения прав на уровне базы используйте отдельную учётную запись MongoDB.
- Память, фоновое наблюдение, загрузка документов и проактивные уведомления в эту версию не входят. Инструкции стиля передаются MCP-клиенту, но окончательное поведение зависит от клиента и модели.

## ChatGPT

Для ChatGPT нужен удалённый HTTPS MCP с Streamable HTTP и OAuth 2.1 (PKCE, проверка scopes/audience, привязка к владельцу/области на сервере). Локальная stdio-регистрация Codex не подключает ChatGPT автоматически. Публичный сервер без авторизации не включён. Расчётный модуль `finance.cjs` можно повторно использовать в будущем HTTP-сервере.

## Проверка

`npm test` — расчёты и валидация. `npm run test:mcp` — отдельная MongoDB и реальный SDK-клиент через stdio; производственная `.env` не читается при тестовых вызовах.
