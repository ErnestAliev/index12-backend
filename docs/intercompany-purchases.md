# Покупки между владельцами счетов

`POST /api/intercompany-purchases` создаёт расход и доход внутри одной рабочей области. Передаются обычные поля расхода/дохода и `purchaseAccountId` — счёт другой стороны. `accountId` принадлежит стороне, указанной в `type`. При `expense` это плательщик, при `income` — получатель.

Оба счёта и их владельцы проверяются по текущей области. Владелец — существующая компания или физлицо. Между счетами одного владельца используется обычный перевод. Сумма проверяется в тиынах; значения двух операций равны по модулю и имеют противоположные знаки.

Связь хранится в `purchaseGroupId` и `purchasePeerId`, собственная компания-контрагент — в `counterpartyCompanyId`. Владельцы и маршрут определяются по счетам на сервере. Обе записи остаются обычными `expense` / `income`, занимают соседние строки и сохраняются в транзакции журнала изменений. Ответ содержит основную запись и `linkedOperations` для синхронного обновления интерфейса.

`PUT /api/events/:id` обновляет всю пару: сумму, дату, положение, маршрут, категорию, проекты и описание. При переносе доходная строка остаётся ниже расходной. `DELETE /api/events/:id` всегда удаляет всю группу, включая доли проектов. Прямое изменение связи и самостоятельное редактирование доли запрещены.

Разбиение по нескольким проектам создаёт две реальные родительские записи и соответствующие доли. Родители исключены из итогов; деньги учитываются по долям один раз. Физлицо внутри пары учитывается как владелец своего счёта, без повторного учёта как внешнего контрагента.

Создание и удаление журналируются всей группой. Восстановление возвращает обе стороны и все доли в соседние свободные строки. Каскадное удаление проекта/счёта/владельца с операциями захватывает всю группу. Перед удалением проекта без операций необходимо убрать его из распределения связанной покупки.

MCP-чтение показывает компанию-контрагента и идентификаторы связи. Изменение, копирование и удаление таких составных операций через существующие одиночные MCP-инструменты отклоняются по общей политике составных операций; редактирование выполняется в форме INDEX12.

Проверки: `node tests/integration/intercompany-purchase.cjs` (изолированная MongoDB replica set), `npm test`; в frontend — `npm run test:purchases`, `npm test`.
