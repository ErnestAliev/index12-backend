# Файлы и действия MCP в чатах

Рабочий чат и календарные задачи — разные сущности. Для рабочего чата используются `index12_chat_*`, для личного помощника — `index12_codex_*`. Владелец получает оба набора через `/mcp`; сотрудник получает только рабочий чат через `/team-mcp` и действует в пределах своей роли. Личный Codex сотрудникам не предоставляется.

## Передача документа в существующую задачу

1. `index12_chat_get_task`: получить задачу, её `version` и прежние вложения.
2. `index12_chat_upload_file`: передать оригинал документа, сохраняя UUID `id` при повторе. Результат — `file.fileId` и SHA-256 исходных байтов.
3. `index12_chat_attach_files`: `id` задачи, свежая `expectedVersion`, `fileIds: [fileId]`. Добавляет файл, сохраняя остальные вложения. `action=remove` убирает только перечисленные файлы.

Для отправки в обсуждение задачи вместо третьего шага используется `index12_chat_send_message` с `taskId` и `fileIds`. Текст необязателен, если есть файл. Загрузка сама по себе ещё не является отправкой.

Поддерживаются любые непустые файлы до 10 МиБ; максимум пять вложений, суммарно до 25 МиБ. Для ChatGPT параметр `file` объявлен через `openai/fileParams` с обязательными `download_url`, `file_id` и необязательными, но объявленными `mime_type`, `file_name`, согласно [OpenAI Reference](https://developers.openai.com/plugins/reference#define-file-inputs). Внешняя загрузка требует HTTPS и публичного IP, закрепляет DNS-адрес, запрещает редиректы, не передаёт токены INDEX12. Временный URL не сохраняется.

Альтернативные источники: `desktopFileId` (свой личный Codex, только владелец), `chatFileId` (доступное вложение рабочего чата), `dataBase64` с `name` (созданные байты). Локальный stdio-сервер дополнительно объявляет `localPath`; удалённый сервер этого параметра не принимает и файлы своего диска не читает. Встроенный серверный помощник принимает `containerId`/`containerFileId` только из контейнера, использованного в текущем запросе. Сгенерированный документ сохраняется также в личном чате.

## Остальные действия

`chat_react` ставит, заменяет или снимает свою реакцию. `chat_mark_read` ставит отметку только по явному поручению; обычное чтение MCP остаётся без отметок. `chat_forward_message` переносит текст и файлы в общий чат или доступную задачу той же рабочей области. `chat_edit_message` меняет свой текст и вложения. Удаление сообщений/задач требует свежей версии; удалённые задачи можно прочитать с `includeDeleted=true` или списком `deleted=true` и восстановить через `chat_restore_task`. Права на согласования сохраняются.

Личный Codex: `codex_chats` → `codex_upload_file` → `codex_send_message`. Отправка возвращает очередь; итог проверяется через `codex_job`. Если Mac отключён, запрос владельца сохраняется до подключения, с `awaitingConnection=true`. Не сообщать о выполнении по одному статусу `queued`. История читается через `codex_get_chat` либо `codex_request_history` и последующий `codex_job`.

## Проекты и фильтры задач

`index12_chat_task_options` возвращает реальные ID и названия проектов текущей рабочей области. При создании или изменении задачи передаётся `projectId` из этого списка; `null` оставляет задачу без проекта. Название берётся сервером из справочника. Недоступные и вымышленные ID отклоняются. Внутренний Codex использует тот же набор инструментов и проверки доступа.

`chat_tasks` и `chat_messages` поддерживают совместные фильтры `projectId`, `person`, `party=kind:id`, `status`, `displayStatus` и срока. `projectId=__none__` выбирает задачи без проекта. `displayStatus` — `planned`, `today`, `done`, `overdue`; срок вычисляется по времени Алматы. Фильтр сотрудника в общем чате выбирает его сообщения и назначенные ему задачи; остальные фильтры задач оставляют только их карточки. Ограничения роли действуют до фильтров.

Календарный `index12_list_tasks` также принимает `projectId`; `get_task` возвращает проект исходной задачи чата. Проект календарной задачи меняется через `update_task`, задачи рабочего чата — через `chat_update_task`, всегда со свежей версией.

## Обновление клиента

Серверный каталог версии 4.4.0 включает новые инструменты. Клиент ChatGPT может хранить каталог, полученный при подключении: после развёртывания обновить список инструментов существующего подключения и начать новый диалог. Публикация INDEX12 Team в каталоге OpenAI отдельно проходит модерацию; обновление серверного кода само по себе не означает одобрения плагина.

Проверки: `npm test`, `node tests/integration/team-chat-mcp.cjs`, `node tests/integration/cloud-chat.cjs`, `node tests/integration/codex-files.cjs`, `node tests/integration/team-chat.cjs`. Они используют изолированную MongoDB, синтетические документы и подменённый OpenAI API; рабочие документы и сообщения не создаются.
