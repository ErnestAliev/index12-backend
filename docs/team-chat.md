# Рабочий чат и задачи

Рабочий интерфейс содержит два основных раздела: «Чат» и «Задачи». Настройка участников доступна владельцу в меню настроек. Заявки на расходы, распознавание PDF как счёта, согласование заявок, прогноз по заявкам и размещение их черновиков на финансовом календаре удалены. Ранее записанные финансовые операции сохраняются. Старые коллекции заявок не удаляются автоматически и больше не используются рабочим чатом.

Владелец входит с текущей сессией INDEX12; приглашённые участники — через отдельную постоянную HttpOnly-сессию чата с телефоном и паролем. Эта сессия не предоставляет доступ к финансовым API. Каждое обращение проверяет активное членство и рабочую область. Только владелец управляет приглашениями и ролями. Смена отображаемой роли не меняет право владельца на администрирование.

## Задачи

`POST /api/team-chat/tasks` принимает UUID `id`, `description`, массив `assigneeIds`, `timing` (`urgent`, `deadline`, `none`), при необходимости `dueDate` (YYYY-MM-DD), `dueTime` (HH:mm) и `fileIds`. Цена и контрагент не нужны. «Себе» преобразуется в ID текущего авторизованного участника. Ответственные проверяются по действующему составу рабочей области. Иерархические ограничения назначения пока не вводятся.

Повтор создания с тем же ID и содержимым возвращает прежнюю задачу. Карточка общего чата имеет тот же UUID и восстанавливается при повторе прерванного создания. `PATCH /tasks/:id` требует `expectedVersion`; изменять задачу могут автор, ответственный и владелец. Автор определяется сервером и не заменяется из тела запроса. Статусы: `open`, `progress`, `delayed`, `done`. `GET /tasks` и `GET /tasks/:id` возвращают задачи и персональную сводку обсуждений.

Создание проходит по шагам «Кому → Когда → Описание». Выбор срока сразу открывает календарь, выбор даты переводит к описанию. Время выбирается на 24-часовом циферблате. Текст, ответственные, дата и время редактируются нажатием на соответствующее значение. Завершённая карточка схлопывается в серую строку и остаётся доступной.

## Переписка и уведомления

`POST /messages` с `taskId` отправляет комментарий в проверенную задачу. `GET /messages?taskId=...&before=...` возвращает историю страницами по 50 сообщений. Комментарии не смешиваются с общей лентой. Ответ на сообщение проверяется в пределах того же обсуждения. UUID отправки предотвращает дубли при повторной передаче. Обычные сообщения сохраняют ответы, реакции, редактирование, пересылку и историю.

`POST /messages/read` подтверждает конкретные видимые сообщения для текущего участника и версии текста. Собственные сообщения не входят в непрочитанные. Сводка карточки содержит последний комментарий, `unreadCount`, `mentioned`, `mentionMessageId`. Отметка @ остаётся после прочтения и снимается после ответа этого участника. Уведомления из меню открывают задачу и соответствующее сообщение. Push сохраняет существующие настройки устройства и добавляет проверяемые task/message ID; переход всегда остаётся внутри текущего сайта и проверяется API.

Файлы загружаются существующим `/files`: до 5 вложений, до 10 МБ на файл, до 25 МБ суммарно. Доступ ограничен рабочей областью. Неприкреплённые загрузки истекают через сутки; прикреплённые сохраняются. Сторонние черновые загрузки нельзя присвоить новой задаче.

## Проверка

Backend: `npm test`, `node tests/integration/team-chat.cjs`. Интеграционный сценарий поднимает отдельную временную MongoDB и настоящий сервер без .env и рабочих данных. Он проверяет вход участников, область доступа, повторные запросы, конкурентные изменения, файлы, 50+ сообщений, непрочитанные и @.

Frontend: `npm test`, `npm run build`, `node tests/browser/team-chat-tasks.mjs` при работающем тестовом сервере (путь к его временному описанию передаётся через `INDEX12_TASK_BROWSER_FIXTURE`). Мобильные проверки безопасных областей описаны в `docs/mobile-layout.md`. Автоматическая геометрия не заменяет проверку реальной клавиатуры на iPhone/Android.

Существующий MCP финансовой системы сохраняется. Отдельные инструменты MCP для задач этого чата в эту поставку не добавляются.
