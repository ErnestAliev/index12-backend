# Компании, контрагенты, КГД и календарь INDEX12

Требование владельца от 03.11.2026: данные контрагентов и компаний получать только напрямую из государственных систем КГД и eGov. Коммерческие агрегаторы, посредники и резервные негосударственные источники запрещены. В реализации нет таких адаптеров, токенов или автоматических переключений на другие источники.

## Что реализовано

- В создании контрагента и компании: БИН/ИИН, прямой поиск юридического лица в eGov, заполнение названия, адреса, руководителя, даты регистрации, вида деятельности и регистрационного статуса. В существующую заполненную карточку реквизиты применяются отдельной кнопкой.
- В редакторе счетов используется существующая строка владельца. Название компании открывает карточку поверх редактора в том же окне. Адрес и вкладки браузера не меняются. Закрытие карточки возвращает к тем же строкам и сохраняет несохранённые изменения редактора. Поле рядом позволяет переименовать владельца, стрелка — выбрать другого. Отдельного списка компаний нет.
- В карточке конкретной компании сохраняются только путь к локальному `.p12`/`.pfx` и пароль. Файл не загружается, не копируется и не читается сервером. Пароль шифруется и не возвращается клиенту; при повторном открытии отображается только признак сохранённого пароля. Сохранение другого пути или смена БИН/ИИН требует повторного ввода пароля.
- Иконка папки открывает локальный диалог выбора файла через NCALayer (`kz.gov.pki.knca.commonUtils.showFileChooser`). NCALayer должен быть запущен. Диалог возвращает настоящий путь к выбранному `.p12`/`.pfx`; браузерный `C:\fakepath` не используется. При отмене выбора старый путь сохраняется. Байты файла не считываются и никуда не передаются.
- После сохранения настроек ЭЦП автоматически запускается обновление реквизитов напрямую из eGov. При повторном открытии карточки с сохранёнными настройками и пустыми реквизитами попытка повторяется. Ошибка источника показывается в карточке; сохранённые настройки при этом остаются. Ручное обновление также доступно. Оно сохраняет пользовательское название компании. Удаление настроек снова отключает кнопку обновления. Сохранение пути и пароля само по себе не подтверждает сертификат или авторизацию в КГД/ИСНА.
- Проверка задолженности напрямую через документированный API КГД. Ответ проверяется на совпадение БИН/ИИН; некорректный ответ или отсутствие доступа не считаются нулевой задолженностью.
- После входа и во время работы открытого приложения запускается неблокирующая проверка подключённых компаний. На сервере повторные обращения ограничены интервалом 15 минут; одновременно опрашиваются максимум две компании. Ручная проверка доступна с интервалом от минуты. MongoDB хранит состояние и блокировку проверки; следующий вход повторяет прерванную проверку после истечения блокировки и интервала.
- По задолженности создаётся одна задача на компанию и БИН/ИИН. Её срок остаётся пустым, поскольку API не сообщает дату уплаты. Повторный ответ обновляет подтверждение. При изменении задолженности или её повторном появлении задача открывается заново. Нулевой ответ обновляет подтверждение, но не объявляет налог оплаченным.
- Встроенный календарь: создание, редактирование, завершение и удаление ручных задач, фильтр компаний, просмотр выполненных задач и просрочек. Даты задач — календарные, время отображается для Asia/Almaty.
- Уведомления браузера включаются пользователем и работают, пока приложение открыто. Повторы ограничены; настройки и история уведомлений разделены по пользователям и рабочим областям. Доставки Web Push при закрытом приложении пока нет.
- Помощник получает задачи и состояние КГД через новые инструменты MCP `index12_list_tasks` и `index12_tax_status`. Эти инструменты предоставляют чтение; автоматическое создание задач ИИ по документам ИСНА ещё не реализовано.

## Доступы, которые нужно получить

На 03.11.2026 приложение опубликовано, отдельный ключ шифрования настроен на backend Render. Проверка рабочего `/api/mcp/business/status` подтвердила: `registryConfigured: false`, `taxConfigured: false`, `edsAuthenticationConnected: false`. Действующие доступы eGov и КГД ещё не настроены; живое получение реквизитов и налоговых данных не подтверждено. Код интеграций проверен с тестовыми ответами. Сохранённые настройки ЭЦП не означают подключение этих источников.

| Доступ | Где получать | Настройка backend |
| --- | --- | --- |
| API открытых данных eGov | [Кабинет разработчика](https://data.egov.kz/profile/apikeylist) | `EGOV_API_KEY` |
| Токен API КГД | [Сервис задолженности КГД](https://portal.kgd.gov.kz/ru/pages/api-services/info-absence-tax-debt), обращение за доступом | `KGD_PORTAL_TOKEN` — заголовок `X-Portal-Token` |
| Токен лицевого счёта каждой компании | КГД, согласно условиям предоставленного доступа | Существующий серверный API `/api/business/companies/:id/connection`; поля токенов в карточке компании не выводятся |
| Ключ шифрования | Сгенерировать в защищённой среде: 32 случайных байта в hex | `INTEGRATIONS_ENCRYPTION_KEY`, ровно 64 hex-символа |

Переменные задать в защищённых настройках сервера, а не в `VITE_*`, исходном коде, переписке или репозитории. Сохранить резервную копию ключа шифрования в хранилище секретов: его потеря потребует повторного подключения компаний.

Токены лицевых счетов хранятся через AES-256-GCM и привязаны к рабочей области, компании и её БИН/ИИН. Пароли ЭЦП также хранятся через AES-256-GCM, дополнительно привязаны к пути файла и отделены от токенов. Если `INTEGRATIONS_ENCRYPTION_KEY` не задан, для паролей ЭЦП допускается отдельный ключ, полученный HKDF-SHA256 из существующего `SESSION_SECRET` длиной от 32 символов. При смене этого секрета потребуется повторное сохранение паролей. Отдельный ключ интеграций предпочтителен.

Секреты не возвращаются клиенту или помощнику. Внешние запросы используют фиксированные государственные HTTPS-адреса, запрещают перенаправления и имеют тайм-аут. При сохранении настроек ЭЦП передаются только локальный путь и пароль; файл не передаётся. Соединение с локальным NCALayer используется только для открытия файлового диалога по нажатию пользователя. Проверка содержимого локального файла и авторизация в налоговом кабинете не подменяются успешным сохранением настроек.

## Государственные протоколы, подтверждённые документацией

1. [Реестр юрлиц eGov](https://data.egov.kz/datasets/view?index=gbd_ul), [API v4](https://data.egov.kz/pages/samples):

   `GET https://data.egov.kz/api/v4/gbd_ul/v1`

   Параметры `apiKey` и `source` с поиском по `bin`. Дополнительно проверяется точное совпадение номера. Разные карточки с одним БИН не выбираются автоматически. Кеш — 15 минут с сохранением времени исходной проверки. Этот набор содержит юридические лица, а не полный реестр ИП/физлиц; поиск ИП по ИИН через него не обещается.

2. [API задолженности КГД](https://portal.kgd.gov.kz/ru/pages/api-services/info-absence-tax-debt):

   `GET https://portal.kgd.gov.kz/services/isnaportalsync/public/tax-debt-info`

   Заголовок `X-Portal-Token`, параметры `taxpayerCode` и `personalAccountToken`. Обрабатываются документированные поля `iinBin`, `totalArrear`, `totalTaxArrear`. Сумма сохраняет знак, полученный из КГД; задолженность определяется по ненулевой величине поля задолженности. Данные банковской оплаты из этого ответа не выводятся.

## Что ещё не подключено

| Требование | Состояние и следующий шаг |
| --- | --- |
| Поиск ИП по ИИН | Получить документированный государственный сервис КГД/eGov и условия доступа. Текущий реестр юрлиц этого не покрывает. |
| Аресты, судебные дела, ограничения, благонадёжность контрагента | Получить соответствующие государственные API и права доступа. В карточке сейчас явно указано «не проверено»; заполненный профиль eGov не означает разрешение на сделку. |
| Вход в ИСНА через ЭЦП | Получить официальный интеграционный протокол авторизации, правила проверки сертификата и доступа к компании. Доступность NCALayer не означает авторизацию ИСНА. |
| Входящие уведомления, камеральный контроль, ФНО, лицевые счета и статусы отчётности | Нужен отдельный официальный доступ ИСНА. API задолженности этих данных не возвращает. |
| Автоматический анализ ИИ | После подключения документов: сохранять исходные документы, источник, идентификаторы и даты; создавать задачи с подтверждением и дедупликацией. Сейчас задачи создаются по проверенному ответу API задолженности. |
| Постоянная проверка при закрытом приложении | Отдельный серверный планировщик/worker и подтверждённый способ продления налоговой авторизации. Текущая проверка запускается открытым приложением. |
| Push при закрытом приложении | Service Worker, серверная доставка Web Push и подписки устройств. |
| Google Calendar | Отложен по решению владельца. |

Ни один из этих пробелов не закрывается коммерческим сервисом или фиктивным успешным результатом. Подпись, подтверждение уведомлений, отправка отчётности и оплата налогов этим модулем не выполняются.

## Проверки

В backend: `node --test tests/business-providers.test.cjs tests/company-eds.test.cjs` и `node tests/integration/business.cjs --browser`.

В frontend: `node --test tests/business-store.test.mjs tests/eds-file-picker.test.mjs`, `npm test`, `npm run build`.

Интеграционный сценарий использует отдельную временную MongoDB и локальные HTTP-серверы, не читает `.env`, не обращается к государственным API и не использует рабочую базу. Проверяются права, изоляция областей, шифрование, дедупликация, повторное открытие задач, отмена запоздавших результатов, инструменты помощника и полный браузерный путь с сохранением данных.
