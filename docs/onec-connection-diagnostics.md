# Сбои облачной цепочки INDEX12 → 1С

Маршрут встроенного чата: интерфейс INDEX12 → серверный CloudChat → runtime MCP → HTTP API INDEX12 → OData 1С Fresh. Сессия Safari для этого маршрута не используется. Отдельный Codex может обращаться к тому же MCP, но смена клиента сама по себе не исправляет транспорт backend → 1С.

При диагностике 11 ноября 2026 года подтверждены разные причины остановок:

- Ранее облачный цикл допускал только 16 ответов модели с вызовами инструментов. Реальный запуск исчерпал их на чтении справочников, до финансовых записей.
- Следующий запуск дошёл до чтения `Catalog_БанковскиеСчета` внутри Code Mode и получил `ONEC_NETWORK_ERROR`. Этот вызов завершился ошибкой примерно за 1,5 секунды; его нельзя объявлять 15-секундным таймаутом. Подкод исходного сетевого исключения не сохранялся, точную транспортную причину старого сбоя установить невозможно.
- При повторной диагностике прямой INDEX12 MCP и независимый коннектор 1С читали публикацию. Тот же банковский запрос трижды успешно выполнен через production HTTP API INDEX12. Это подтверждает работоспособность маршрута на момент проверки; права записи таким чтением не проверяются.

Подготовленные изменения:

- Облачный цикл ограничен 64 ответами модели вместо 16. Общий срок работы задания и проверки состояния выполнения сохраняются.
- При кратком сетевом сбое HTTP GET повторяется один раз внутри прежнего общего лимита 15 секунд на запрос. Ошибки прав, сертификатов и исчерпанный срок не запускают такой повтор.
- POST создания, PATCH изменения и команды проведения не повторяются автоматически. При неизвестном результате сохраняются прежний operationId и сверка нативного журнала.
- Метаданные публикации кэшируются на пять минут, максимум для восьми сочетаний адреса и учётных данных; ключи хэшируются. Одновременная загрузка одинаковой публикации объединяется. Документы, суммы, остатки и DataVersion не кэшируются.
- `onec_status` запрашивает свежую публикацию; `onec_schema(refresh=true)` обновляет кэш явно.
- Диагностика `onec.transport` содержит сетевой код, этап headers/body, длительность, число попыток и признак чтения/повтора. Адреса, учётные данные, фильтры и содержимое документов в этот журнал не попадают.

Проверки: `tests/onec-transport.test.cjs` (обрыв соединения/тела, отсутствие повторов записи, изоляция и срок кэша), `tests/integration/cloud-chat.cjs` (20 чтений перед записью тестовой задачи), `tests/integration/onec-purchases.cjs` (идемпотентность, потеря ответа, версии и права). Интеграционные записи создаются только во временной локальной базе и фиктивной 1С.
