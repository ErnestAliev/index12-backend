# Index12 → Codex: локальный пилот

Финансовые данные читает существующий MCP `index12`. Сообщения обрабатывает Codex App Server под уже настроенным локальным аккаунтом. Отдельный ключ внешней модели не используется.

Правило источника данных хранится в `codex/context.md` и передаётся как `developerInstructions` при создании и возобновлении каждого разговора из INDEX12. Вопросы относятся к текущей рабочей области; факты сначала проверяются через MCP index12. Внешние источники используются только по явному запросу. Правило применяется к существующим чатам при следующей отправке сообщения и не меняет остальные разговоры Codex.

## Запуск

Режим по умолчанию — общий сервер Codex. Запустите `codex app-server daemon start`, затем в каталоге backend выполните `npm run desktop:bridge`. Мост запускается в фоне и не зависит от открытого терминала; повторный запуск проверяет уже работающий процесс. Для отладки в текущем терминале используйте `npm run desktop:worker`. Worker подключается к существующему серверу через закрытый Unix socket и не запускает отдельный исполнитель в этом режиме. Состояние «подключён» означает, что worker поддерживает связь с общим сервером. Открытое окно desktop не требуется для отправки и чтения истории. Подключение самого desktop к тому же серверу показывается отдельным полем статуса.

В установленной версии desktop обнаружен экспериментальный параметр `CODEX_APP_SERVER_WS_URL`. Скрипт `codex/launch-desktop.command` запускает desktop с этим параметром через локальный адаптер к общему серверу. Сначала пользователь должен полностью закрыть приложение через ⌘Q. Скрипт не закрывает его сам. Пока такой запуск реального desktop не проверен пользователем, совместная работа приложения и сайта не считается подтверждённой. Обычный запуск из Dock без этого параметра возвращает штатный режим.

Адаптер слушает только 127.0.0.1, требует случайный секрет в адресе подключения и отклоняет браузерные Origin. Адрес хранится только на Mac в `.desktop-bridge.local.json` с правами 0600 и не выдаётся HTTP API сайта. Скрипт запуска не печатает секрет.

На Mac должен быть доступен установленный `codex`, локальная конфигурация MCP `.mcp.local.json` и существующее подключение `.env` к базе Index12. Секреты остаются на Mac и не передаются в браузер. При необходимости путь к исполняемому файлу задаётся `INDEX12_CODEX_BIN`, папка проекта — `INDEX12_ASSISTANT_ROOT`.

Первый режим с отдельным процессом сохранён только для явной диагностики через `INDEX12_CODEX_TRANSPORT=standalone`; автоматического перехода на него нет.

На сайте используется кнопка **Codex** в правой панели под генератором квитанций. Чат открывается отдельным окном поверх сервиса; левый край меняет ширину, верхний — высоту, угол — оба размера. Размер сохраняется между открытиями. На телефоне эта же кнопка открывает компактное окно Codex. Кнопка **Новый чат** начинает тему; сообщения продолжают выбранный разговор. Переключение календаря и смена суток не создают и не удаляют эти чаты. Старый AI через OpenAI API удалён.

## Хранение и доступ

- Исходная переписка хранится в разговорах Codex. Запрос `history` читает её через `thread/items/list` с пагинацией.
- Mongo хранит только привязку чата к пользователю, рабочей области и `threadId`, а также временную очередь доставки. Завершённые задания удаляются через 24 часа. История Codex не удаляется.
- Локальный worker обслуживает только пользователя и рабочую область из конфигурации MCP. HTTP API проверяет сессию и актуальное членство в рабочей области. Чужой `chatId` не даёт доступа к истории.
- У одного чата одновременно выполняется одно задание. Повтор одного `requestId` возвращает прежнее задание. После сбоя выполнявшийся запрос не повторяется автоматически: сначала нужно проверить историю.
- Все чаты не склеиваются в один контекст. Новый разговор получает новый `threadId`; продолжение использует прежний. Пагинация отображения истории не обрезает память разговора у Codex.
- Перед каждым сообщением worker проверяет права через аутентифицированный API MCP с привязкой пользователя и рабочей области. Для разрешённых инструментов в `direct` используется автоматическая проверка согласия и политики App Server (`auto_review`); реальные запреты не переопределяются. Необработанный дополнительный запрос разрешения возвращает `APPROVAL_UNAVAILABLE`, а не выдуманный отказ пользователя. Другие настроенные финансовые MCP отключены в этих разговорах.
- Записи одного web-хода выполняются последовательно. После первой ошибки закрывается приватный журнал выполнения: следующие записи блокируются до нового запроса. `expectedVersion` не заменяется автоматически. Чат показывает подтверждённые результаты, в том числе при частичном выполнении; неподтверждённый ответ API требует свежего чтения перед повтором. После ошибки неподтверждённые заявления модели об успехе не отображаются и при повторном открытии истории.

## Ограничения пилота

Mac, общий сервер и worker должны быть включены. Для отображения тех же разговоров в desktop приложение также должно подключиться к этому серверу. Два клиента общего сервера успешно проверены: второй клиент получает `thread/started` и `thread/status/changed`, видит ту же историю. Проверены адаптер и его ограничения доступа. Переключение самого desktop и появление новых чатов в нём ещё требуют проверки после перезапуска. Успешный обмен между двумя тестовыми клиентами не означает, что эта проверка завершена.

Изменения нужно отдельно развернуть на backend и frontend, чтобы изменения появились на опубликованном сайте. Локальная проверка не меняет опубликованные сборки.

## Чат на сайте

Codex использует компонент ввода: Enter отправляет, Shift+Enter переносит строку, микрофон заполняет текст. Можно прикрепить до пяти файлов любых расширений: до 10 МБ каждый, до 25 МБ суммарно. Изображения передаются как изображения, остальные документы доступны Codex для чтения из локальных копий; макросы не запускаются. Имена и ссылки на оригиналы сохраняются в истории. Принятые файлы хранятся в Mongo отдельно от временных заданий, доступ ограничен автором, рабочей областью и чатом; неотправленные загрузки удаляются через 24 часа. На Mac копии лежат в `.attachments` внутри рабочей папки помощника. Возможность анализа зависит от формата, шифрования и наличия подходящих средств чтения; при ошибке Codex должен сообщить конкретное ограничение. Состояние связи обновляется каждые 5 секунд. Последняя полученная страница истории доступна из временного результата задания (до 24 часов), даже если Mac отключился; исходная история остаётся в Codex.
