# Index12 → Codex: локальный пилот

Финансовые данные читает существующий MCP `index12`. Сообщения обрабатывает Codex App Server под уже настроенным локальным аккаунтом. Отдельный ключ внешней модели не используется.

## Запуск

В каталоге backend выполните `npm run desktop:bridge`. На Mac должен быть доступен установленный `codex`, локальная конфигурация MCP `.mcp.local.json` и существующее подключение `.env` к базе Index12. Секреты остаются на Mac и не передаются в браузер. При необходимости путь к исполняемому файлу задаётся `INDEX12_CODEX_BIN`, папка проекта — `INDEX12_ASSISTANT_ROOT`.

На сайте используется вкладка **Codex** рядом с **AI**. Кнопка **Новый чат** начинает тему; сообщения продолжают выбранный разговор. Переключение календаря и смена суток не создают и не удаляют эти чаты. Предыдущий AI-помощник остаётся отдельной вкладкой.

## Хранение и доступ

- Исходная переписка хранится в разговорах Codex. Запрос `history` читает её через `thread/items/list` с пагинацией.
- Mongo хранит только привязку чата к пользователю, рабочей области и `threadId`, а также временную очередь доставки. Завершённые задания удаляются через 24 часа. История Codex не удаляется.
- Локальный worker обслуживает только пользователя и рабочую область из конфигурации MCP. HTTP API проверяет сессию и актуальное членство в рабочей области. Чужой `chatId` не даёт доступа к истории.
- У одного чата одновременно выполняется одно задание. Повтор одного `requestId` возвращает прежнее задание. После сбоя выполнявшийся запрос не повторяется автоматически: сначала нужно проверить историю.
- Все чаты не склеиваются в один контекст. Новый разговор получает новый `threadId`; продолжение использует прежний. Пагинация отображения истории не обрезает память разговора у Codex.
- На этапе пилота дополнительные запросы разрешений отклоняются с сообщением о необходимости подтверждения в desktop. Другие настроенные финансовые MCP отключены в этих разговорах.

## Ограничения пилота

Mac и worker должны быть включены. App Server запускается отдельным процессом; принадлежность к проекту сохраняется через официальный `projectId`, однако отображение этой привязки и обновление чатов в текущей версии desktop требуют отдельной проверки. Успешный обмен сообщениями не означает, что вся интеграция с боковой панелью подтверждена.

Изменения нужно отдельно развернуть на backend и frontend, чтобы вкладка появилась на опубликованном сайте. Локальная проверка не меняет опубликованные сборки.
